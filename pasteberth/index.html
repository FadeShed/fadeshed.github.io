01 / NOT ROLES — CONTEXTS

Use it alone.
Or between anything.Seul.
Ou entre n’importe quoi.

Pasteberth does not care who is on either side. A person, an agent, a script or another tool can use whichever interface fits its environment.

Pasteberth ne décide pas qui se trouve de chaque côté. Une personne, un agent, un script ou un autre outil utilise simplement l’interface adaptée à son environnement.

01 / PERSONAL

Paste now. Copy later.

Keep a screenshot, note or file in a zone instead of depending on the last thing in your clipboard.

02 / DOCUMENTS

Drag it in. Pick it up.

PDFs, spreadsheets, archives and other allowed files can cross working contexts without SSH gymnastics.

03 / AGENTS

Give agents a handoff point.

Paths in, artifacts out. Agents can work with ordinary files instead of a bespoke transfer protocol.

04 / TOOLS

Skip another custom GUI.

A CLI or script can keep producing files while Pasteberth provides a shared place to inspect and retrieve them.

03 / THE FILESYSTEM IS AN INTERFACE

Already on disk?
Leave it there.

Your tools already know how to produce files. Pasteberth does not force those bytes through the network just to put them back beside the producer.

cp + register · no network

A file stays a file.

Copy it into a zone, then register it. register validates the existing regular file and creates or refreshes its sidecar without rewriting the data or contacting the daemon.

report.pdf + report.pdf.json
# already on the same filesystem cp report.pdf /repo/atlas/ignoredbygit/exchange/ pasteberth register /repo/atlas/ignoredbygit/exchange/report.pdf # or let the daemon publish it pasteberth drop --zone atlas report.pdf
04 / CONVENTION OVER CONFIGURATION

Create the directory.
The exchange point appears.

Zone collections can discover project exchange directories from a filesystem convention. Project templates can provision the directory; Pasteberth discovers matching zones on refresh, without per-project config edits or daemon restarts.

/repo/ ├── atlas/ │ └── ignoredbygit/ │ └── exchange/ ├── beacon/ │ └── ignoredbygit/ │ └── exchange/ └── new-project/ └── ignoredbygit/ └── exchange/ ← discovered
zero-touch project discovery

No SSH just to add another workspace.

When your project factory, template or deployment process follows the convention, the filesystem itself becomes the registration mechanism.

Important: discovery is background scanning, not a filesystem watcher, and candidate directories must satisfy the configured collection rules and permissions.
