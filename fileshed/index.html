01 / THE TOOLKIT

Storage was the foundation.
The work was the point.

FileShed brought a set of working tools into the conversation, with a shared model for files, zones, permissions and results.

/01

Data, without flooding the chat.

Import CSV into SQLite, query it, calculate new columns and export results. Command output can go straight to disk; SQL results can become a CSV instead of thousands of chat tokens.

SQLite · CSV import/export · jq · output redirection

/02

Files into finished things.

Convert documents with Pandoc, process media with FFmpeg, inspect binary data, unpack archives and package deliverables. Download links bring the result back into Open WebUI.

Documents · media · archives · authenticated downloads

/03

Edit, save, or take a step back.

Change text by line or pattern, patch bytes, or use a locked working copy with explicit save and cancel. The Documents and Groups spaces add automatic Git versioning.

Precise edits · working copies · locks · Git history

/04

Tools that explain themselves.

The model can ask for task-specific how-tos, discover installed commands and inspect configuration. Structured errors include context and hints to help it correct a call rather than repeat it blindly.

shed_help · shed_allowed_commands · contextual hints

External commands must be installed in the Open WebUI environment. Network access is disabled by default. PDF creation and some image operations need additional tools.

02 / FROM PROMPT TO RESULT

One request.
A chain of useful operations.

The repository documents a country-data workflow using a 20B model. Its strength was composition: familiar tools, connected by the model, producing an actual deliverable.

01Get the data onto the workbench +

With network access explicitly enabled, download JSON to a file and transform it to CSV with jq. The dataset does not need to be pasted into the conversation.

shed_exec(zone="storage", cmd="curl",
  args=["-L", "-o", "countries.json", URL])
02Turn files into queryable data +

Import CSV, add a density column, calculate it and sort the results in SQLite. These are tool calls operating on stored data, not arithmetic improvised in prose.

shed_sqlite(zone="storage", path="data.db",
  import_csv="countries.csv", table="countries")
03Export, package, hand it back +

Export the query to CSV, bundle the output and create an authenticated Open WebUI download link.

shed_zip(zone="storage", src="results",
  dest="countries_density.zip")
shed_link_create(zone="storage",
  path="countries_density.zip")

Calls above illustrate the documented sequence; they are not a complete runnable script. The original run includes retries and continuation prompts, not a guarantee of a fixed number of turns.

Power, with explicit boundaries.

Allowlisted commands, path checks, quotas, timeouts and administrator-controlled network modes. Group files have owner, group and owner_ro write modes.

These are application-level safeguards, not an OS isolation boundary. The historical AI-assisted reviews are not an independent security certification.

What made it agent-oriented? +

Only the public shed_* tools were intended for model exposure; internal logic lived in _FileshedCore. Task-oriented help, output limits and corrective hints treated model calls as a first-class interface.

What else is in the source? +

The supplied 1.1.0 source also contains optional personal-file encryption using AES-256-GCM and Argon2id. It is not universal end-to-end encryption: groups stay unencrypted, keys are used at runtime, and shell commands see encrypted bytes. Loss of the key means loss of access.

Retired

Retired.
Not erased.

A useful tool is allowed to finish its job.

I retired FileShed because Open WebUI’s OpenTerminal now covers much of what I needed it for. That does not make the work disappear: the code, the workflows and the design decisions remain here for people to learn from.

FileShed is part of the story behind FadeShed: making conversational models useful beyond the conversation, and sharing the tools that made it possible.

This is a project retrospective, not a promise of ongoing maintenance or compatibility with current Open WebUI versions.
